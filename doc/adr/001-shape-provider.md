# ADR 001：图形注册与 SVG 读回

状态：图形扩展点已实现；通用插件加载事务尚未实现。

## 问题

Phase 1 的 `ShapeFactory` 枚举六种图形，`SvgCodec` 自行创建工厂。只给创建命令增加注册入口，会导致新增类型无法读回，help 也可能与实际能力不一致。

## 决策

- 在内核侧定义 `ShapeProvider`，提供名称、帮助文案、创建、读回匹配和读回构造接口。
- `ShapeFactory` 只管理注册与调用，不导入六类图形实现。`BuiltinShapesPlugin` 提供六个类实例，由宿主 `DefaultShapes` 显式装配。
- `main.ts` 将同一个注册表注入创建命令和 SVG 编解码器；help 从已注册提供器读取图形参数。
- XML 层保留语法、命名空间、长度规范化、自动 id 和全局重复 id 校验。子树解析完后，再将标签、属性、子节点和文字交给提供器，避免返回未组装完的复合图形。
- `matchesSvg` 只判断、不修改对象。多个提供器命中时选择最高 `svgPriority`；最高优先级并列时报错，不按注册顺序静默覆盖。
- 普通 SVG 提供器的优先级为 0。未来识别 `data-kind` 的提供器使用更高优先级；未安装专用提供器时，普通 `g` 仍能保留属性与子树。这一通用降级路径已用测试图形验证，尚不代表 `box` 插件已实现。
- 名称重复时报 `duplicate registration: shapes/<name>`；非法元数据或缺失方法报 `invalid shape provider`；返回对象不是 `Shape` 或 id 不符时报 `shape provider returned invalid shape: <id>`。

## 失败与边界

创建仍由 `EditCommand` 的快照事务保护。读回先构造新文档，完整成功后才替换会话；提供器抛错不会改变原文档和历史。提供器必须检查自身结构不变量，框架不会通过名称识别具体复合图形。

当前直接注册只保证单个注册不覆盖已有项，不保证整个插件多项注册的原子性。后续统一宿主必须增加暂存、清单校验和整包提交/回滚，代码与配置装配都必须经过该路径。

## 验证

`test/shape-provider.test.ts` 覆盖空注册启动、内置插件注册、自定义创建、撤销重做、专用读回、缺省降级、匹配冲突及失败保护。原有 95 项行为断言保留，只将默认能力移到测试组合根显式装配。

`scripts/check-phase1.ps1` 从 `final` 导出并编译基线，用独立工作目录回放基础会话及流程图会话，比较输出与保存文件字节。当前 help、tree 等会话输出及两个 SVG 文件一致。完整 Phase 2 的新插件会话和双装配验收另行补充。
