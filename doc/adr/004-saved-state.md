# ADR 004：保存点、dirty 语义与复合容器保护

状态：通用能力与 modified-star 标签插件已实现，内容比较和标签共存测试通过。

## 保存点与标签约定

采用“当前内容与最近成功 read/save 不一致”的 dirty 语义，undo 回到保存内容时星号应消失，redo 后内容再次不同时恢复。新建未保存的文档没有保存点，根与新建节点应视为未保存。子节点内容或顺序变化向祖先容器和 SVG 根传播；多个标签仍按注册顺序拼接。这些是后续 modified-star 插件需要实现和验证的契约，当前并未输出星号。

`EditorSession` 持有内部保存快照。成功 read/save 更新它，init 清除它；普通编辑、canvas、undo、redo 和失败读写不更新它。显式另存更新保存内容基线，但不改变 Phase 1 的默认读入路径。getter 返回克隆，外部不能改写内部保存点。

保存前先构造快照，避免克隆失败却已写出文件；只有仓库保存成功后才发布保存点。读取则在新文档和快照均构造成功后替换会话。树渲染每次只获取一份快照，通过 TreeContext 传给标签，标签无需访问私有字段或订阅内部历史实现。标签必须保持领域对象只读，状态封装在实例字段中；快照不等于对任意插件代码的安全隔离。

## 复合容器与显示钩子

公开 `Shape.assertCanRemove(child)` 与 `assertCanUngroup()` 多态钩子，默认不增加限制。Group.remove 调用移除检查，文档分组与解组先检查所有来源子部件，再改变父子关系。复合图形通过覆盖钩子保护必要子部件，内核不识别具体插件名称。整个复合图形被外部普通容器删除时不逐个移走内部部件，因此仍可以整体删除。

插件图形必须实现保留具体类型及不变量的 clone，以便历史快照恢复后保护仍有效。当前采用严格策略：必要子部件的 remove 被禁止，因此 front/back 等借助 remove 的结构操作也可能被拒绝；后续 box 插件须明确记录其选择。

`treeLabel` 与 `creationMessage` 默认保留 Phase 1 输出，插件可覆盖以区分树中的 SVG 标签、编辑消息中的领域类型，以及复合图形创建说明，而不修改渲染器或创建命令。

## 验证

`test/framework-capabilities.test.ts` 使用独立受保护容器替身，覆盖删除、移出、分组、解组、整体删除、撤销重做和保留具体类型；另验证保存点建立、隔离、失败读写、undo/redo、另存路径及树上下文。实际 box 与 modified-star 的业务验收将在各自插件提交中完成。
